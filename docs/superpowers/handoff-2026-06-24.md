## What the harness is for
A way to *feel* the STT→brain→TTS loop end-to-end and measure latency, without the mobile
device or WebSocket server. It drives the production `AgentBrain` + `AgentSession` +
`StreamingTTS`. The **safety invariant still holds**: all reasoning/escalation lives in the
text brain; this is just an alternate ingestion for local testing.

## `scripts/live_voice_loop.py` — how it works now
- **Streaming STT (realtime websocket).** Mic streams continuously to
  `client.realtime.connect(extra_query={"intent": "transcription"})`, session configured
  for `server_vad` + `gpt-4o-mini-transcribe`, pcm 24 kHz. The model transcribes **as you
  speak**; **server-side VAD** detects end-of-speech. Events used: `speech_stopped`,
  `conversation.item.input_audio_transcription.delta`/`.completed`.
- **Brain + TTS.** On each finalized transcript → `session.handle_patient_input(...)` →
  streamed TTS playback (`audio.speech.with_streaming_response`, `response_format="pcm"`),
  first audio plays on the first chunk.
- **Barge-in.** Mic stays open during playback; a local energy detector (echo-calibrated
  threshold) sets an `asyncio.Event` that aborts TTS mid-sentence, and forwards the onset
  frames to the socket so the interruption gets transcribed.
- **Echo calibration.** During the spoken greeting it measures the agent's *own* level at
  the mic (95th-percentile RMS) and sets the barge bar to `max(level*1.5, ambient_thresh)`,
  so the agent can't interrupt itself. Headphones remove the leak entirely.
- **Warm-up.** Tiny throwaway brain+TTS calls and the realtime socket open run
  concurrently with calibration, hiding cold-start.

### IMPORTANT architecture note
The **listen side bypasses the production `VoiceLoop` / `SpeechToText` pipeline** and talks
to the realtime transcription socket directly. This is a deliberate **latency experiment**,
not a product-direction change. `config.REALTIME_MODEL` is still deprecated; the product
path remains STT→text-brain→TTS so escalation/safety stays in the inspectable text brain.

## Latency findings (measured live this session)
Per-turn pipeline is serial. Original buffered pipeline vs. the streaming version:

| | end-of-speech detection | STT | brain | TTS (to first audio) | total to first audio |
|---|---|---|---|---|---|
| **Before** | 0.6 s local hangover | 1.34 s (buffered upload) | 2.74 s | 2.27 s (full synth) | **6.95 s** |
| **After** | server VAD (`silence_duration_ms`) | ~0.25 s (streamed) | ~2.7 s | ~0.30 s (streamed) | **~3.25 s** |

**The brain (`gpt-5.4-mini`, ~2.7 s) is now the dominant cost.** STT and TTS are near-instant.
Remaining lever discussed but not built: a `--brain-model` flag to A/B a faster model
locally (without touching `config.BRAIN_MODEL`).

## How to run / tune
```powershell
.venv\Scripts\python scripts\live_voice_loop.py   # Ctrl+C to quit
```
Tunables at the top of the file:
- `SERVER_VAD_SILENCE_MS` (400) — end-of-speech patience (↓250 snappier, ↑700 more patient).
  This replaced the old local `SILENCE_HANGOVER`.
- `BARGE_MARGIN` (1.5) / `BARGE_ONSET_FRAMES` (5) — interrupt sensitivity.
- `THRESHOLD_FACTOR` / `THRESHOLD_FLOOR` — ambient speech-onset sensitivity.

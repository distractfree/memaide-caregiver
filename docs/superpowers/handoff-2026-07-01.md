### Real SDK API confirmed (was the plan's #1 unknown)
Inspected the downloaded jars with `javap`. Key facts baked into the code:
- Lifecycle: `Wearables.initialize(ctx)` → `startRegistration(activity)` (one-time, Activity-bound) →
  `createSession(AutoDeviceSelector())` → `session.start()` → `session.addStream(StreamConfiguration(
  VideoQuality.LOW, fps, compressVideo))` → `stream.start()` → `stream.videoStream`.
- `VideoFrame(buffer: ByteBuffer, width, height, presentationTimeUs, isCompressed, isCodecConfig)`.
- `Stream` exposes **only video** — no audio → glasses audio is Bluetooth SCO (validated `AudioEngine`).
- Kotlin sees `registrationState`/`isDevMode` as properties (not getters).

## Designed this session (spec committed, not yet planned/implemented)
**Spec:** `docs/superpowers/specs/2026-07-01-glasses-vision-trace-and-whatsapp-design.md`

Two small, independent features (build **Part A first**):
- **Part A — glasses vision trace.** Real frames from the phone → WS server; a new injectable
  **`VisionObserver`** (default off in `ServerDeps`, so existing tests are untouched) logs per
  described frame: `[vision]` context, and on escalate `[brain]` reaction + `[escalation]`. New
  `scripts/run_bridge_server.py` wires the real describer/brain + `FileSessionRecorder` and prints
  the trace. Phone gets a **minimal `MainActivity`** (register + Start/Stop) and a **frames-only**
  flag on `MediaBridgeService` (no audio). Decisions: frames-only; brain reaction only on escalate.
- **Part B — WhatsApp notify.** New `src/memaide/notify/whatsapp.py` `WhatsAppSender`
  (`send_text`/`send_template` via Meta **WhatsApp Cloud API**), built + unit-tested standalone
  (mocked HTTP) with `scripts/send_whatsapp.py` for real sends, then wired so escalation fires a
  WhatsApp with a per-episode **cooldown**. Env: `WHATSAPP_TOKEN`, `WHATSAPP_PHONE_NUMBER_ID`,
  `WHATSAPP_TO` (README, no `.env.example`). Note the 24h-window / approved-template first-contact rule.
